# 오늘 뭐 입었지? (Today's Outfit) MVP PRD

## 1. 개요

**목적**: 내가 실제로 어떤 옷을 입고 살아가는지 기록되지 않아, 옷장 속 옷과 실제 착용 패턴 사이의 간극을 파악하기 어려운 문제를 해결한다.
**타겟 사용자**: 자신의 옷 입는 습관을 매일 짧게 기록하고, 나중에 "나는 주로 어떤 옷을 입는가"를 데이터로 돌아보고 싶은 개인 사용자(모바일 중심 이용자).

## 2. 배경 및 문제 정의

- "내가 어떤 옷을 가지고 있는가"는 옷장을 열어보면 알 수 있지만, "나는 실제로 어떤 옷을 입고 살아가고 있는가"는 기억에 의존할 수밖에 없어 정확히 알기 어렵다.
- 핵심 질문은 소유가 아니라 **실제 착용 행위**이며, 이를 하루 단위로 가볍게 기록해 누적하면 자신만의 옷 입는 방식을 발견할 수 있다.
- 따라서 이 프로젝트는 "옷장 관리 앱"이 아니라 **개인 옷장 로그(하루 착장 기록) 앱**으로 정의한다.

## 3. 타겟 사용자

- 매일 무엇을 입었는지 간단히 기록하고 싶은 1인 사용자
- 이미 가진 옷을 어떻게 조합해 입는지 되돌아보고 싶은 사용자
- 별도 설치형 앱보다 모바일 웹으로 가볍게 기록하길 원하는 사용자

## 4. 사용자 여정

```
1. 홈
   ↓ 비로그인 상태 감지 → 자동 리디렉션

2. 로그인 페이지
   ↓ 계정 없음 → 회원가입 페이지 → 가입 완료 → 홈
   ↓ 로그인 성공
   
3. 홈 (로그인 상태)
   ↓ 오늘 기록 여부 확인
   
   [오늘 미기록] → "기록하기" 버튼 → 오늘의 착장 기록 페이지
   [오늘 기록 완료] → 하단 탭바로 다른 화면 이동
   ↓

4. 오늘의 착장 기록 페이지
   - 대표 착장 사진 1장 업로드
   - 옷장에서 상의/하의/신발/아우터 등 아이템 선택
   ↓ 저장

5. 저장 완료 → 홈 또는 캘린더로 이동
   ↓ 이후 자유 이동(하단 탭바)

   옷장 페이지 ↔ 아이템 등록/수정/삭제
   캘린더 페이지 ↔ 날짜 선택 → 해당 날짜 착장 상세 보기/수정
   통계 페이지 ↔ 착용 빈도 확인
   마이 페이지 ↔ 계정 확인/로그아웃
```

### 내비게이션 구조 (하단 탭바, 로그인 후)

`홈 · 옷장 · 캘린더 · 통계 · 마이`

- "오늘의 착장 기록" 화면은 별도 탭이 아니라 홈의 버튼(또는 플로팅 버튼)을 통해 진입한다.
- 비로그인 상태에서는 탭바 대신 로그인/회원가입 화면만 노출된다.

## 5. MVP 기능 명세

### 5.1 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 오늘의 착장 사진 업로드 | 하루에 하나의 대표 착장 사진을 선택해 업로드 | 서비스의 핵심 기록 행위 | 오늘의 착장 기록 페이지 |
| **F002** | 착장-아이템 연결 | 업로드한 착장 사진에 상의/하의/신발/아우터 등 옷장 아이템을 다중 선택으로 연결 | "어떤 옷을 입었는지" 구조화된 기록의 핵심 | 오늘의 착장 기록 페이지 |
| **F003** | 옷 아이템 등록 | 카테고리(상의/하의/신발/아우터 등)와 사진을 지정해 옷장에 아이템 추가 | 착장 기록의 전제가 되는 기초 데이터 | 옷장 페이지 |
| **F004** | 옷 아이템 수정 | 등록한 아이템의 이름/카테고리/사진 수정 | 잘못 등록한 정보 정정 | 옷장 페이지 |
| **F005** | 옷 아이템 삭제 | 더 이상 소유하지 않는 아이템 삭제 | 옷장 데이터 정확성 유지 | 옷장 페이지 |
| **F006** | 옷장 목록 조회 | 카테고리별로 등록된 아이템을 목록으로 확인 | 착장 기록 시 아이템 선택의 기반 | 옷장 페이지 |
| **F007** | 캘린더 기록 표시 | 착장이 기록된 날짜를 캘린더에 시각적으로 표시 | 기록 누적을 한눈에 확인 | 캘린더 페이지 |
| **F008** | 날짜별 착장 상세 조회 | 캘린더에서 특정 날짜 선택 시 해당 착장 사진과 연결 아이템 상세 확인 | 과거 기록 탐색의 핵심 | 캘린더 페이지 |
| **F009** | 스타일 통계 | 아이템별/카테고리별 착용 횟수 집계 및 표시 | "무엇을 자주 입는지" 발견이라는 프로젝트 목적과 직결 | 통계 페이지 |

### 5.2 MVP 필수 지원 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|

### 5.3 MVP 이후 기능 (제외)

- 다크 모드 (별도 "향후 고려사항"에서만 다룸)
- 프로필 상세 관리(아바타, 자기소개 등)
- 옷 아이템의 브랜드/가격/구매처 등 상세 메타데이터
- 태그 기반 고급 검색 및 필터링
- 소셜 기능(팔로우, 공유, 좋아요)
- 실시간 알림/기록 리마인더
- 착장 사진 다중 업로드(여러 장)
- 데스크톱/태블릿 대응

### Supabase 역할 설명 (쉬운 설명)

백엔드 서버를 직접 만들지 않고도, Supabase 하나로 다음 세 가지를 해결한다.

1. **인증(Auth)**: 회원가입/로그인/로그아웃을 대신 처리해준다. 이메일·비밀번호 로그인과 구글 로그인 기반은 이미 구현되어 있어, 이번 프로젝트는 이를 그대로 사용한다.
2. **데이터베이스(Database)**: `outfits`, `clothing_items`, `outfit_items` 같은 표 형태 데이터를 저장하고 불러오는 저장소 역할을 한다. PostgreSQL이라는 관계형 데이터베이스를 기반으로 하며, Supabase가 서버 관리 없이 이를 제공한다.
3. **스토리지(Storage)**: 착장 사진, 옷 아이템 사진 같은 이미지 파일을 저장하는 공간이다. 업로드된 이미지의 접근 경로(URL)를 데이터베이스의 `photo_url` 필드에 저장해 연결한다.

즉, "로그인 처리", "데이터 저장", "사진 파일 저장"이라는 백엔드 역할 세 가지를 Supabase 하나가 모두 담당한다.

## 9. 비기능 요구사항

- **지원 환경**: 모바일 환경만 지원한다. 데스크톱, 태블릿 레이아웃은 이번 MVP 범위에 포함하지 않는다.
- **디자인 톤**: 주요 브랜드 컬러는 민트, 그레이 두 가지를 기본으로 한다.
- **다크 모드**: 이번 MVP 범위에서 제외한다. (자세한 내용은 10. 향후 고려사항 참고)

## 10. 향후 고려사항

- 다크 모드 지원 (MVP 완료 후 별도 검토)
- 데스크톱/태블릿 반응형 대응
- 프로필 상세 관리(아바타, 자기소개)
- 옷 아이템 브랜드/가격/구매처 등 상세 메타데이터
- 착장 사진 다중 업로드
- 태그 기반 검색 및 필터링
- 소셜 기능(팔로우, 공유)
- 알림/리마인더
- AI 기반 코디 추천 및 심화 통계
